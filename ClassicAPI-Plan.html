An analysis of BigWigs 2.0.6 (revision 30146, your fork KameleonUK/BigWigs) for a ClassicAPI-only build. Reply with the item IDs you want done, for example “B1–B4, O1, O6, skip O15”.

Summary

BigWigs is the Turtle WoW boss-mod: timer bars, warning messages, sounds, raid marks and raid syncs for about 150 encounters, plus raid-utility plugins (cooldown tracking, proximity, pull timer, version check). It is built on Ace2.

69,100lines of BigWigs code
151boss modules, 51,000 lines
34plugins, 14,800 lines
26embedded Ace2 libraries, 1.4 MB
1,025combat-chat event registrations

API reference used: the latest docs/API.md from GitHub (29,216 lines). It was newer than your local copy, so the AddOns-root files were rotated: API.md is now the previous release (27,166 lines) and API-Latest.md the new one.

Coverage: Core.lua, Options.lua and the plugins with ClassicAPI relevance were read closely. The 151 boss modules share one template, so they were pattern-scanned across every file (events, triggers, targeting, GUID and aura use, globals, Lua 5.0 traps), with representative modules read in full. Every file passed a syntax check, and the loop-key checker found no real hits in BigWigs’ own code.

Headline: the five changes worth the most

  1. Combat-log dispatcher for boss modules (O1–O4). Boss modules listen to about 11 chat events each and match English sentences. ClassicAPI’s structured combat log gives the spell ID, source and target GUIDs, and resist or immune results. That makes triggers exact and independent of client language. Engage, boss-death and cast detection can also stop polling.
  2. Aura and GUID helpers without SuperWoW quirks (O5, O6). Fixes a crash path (B1) and debuff checks that miss Turtle’s overflow debuffs (B4), and replaces 24 raid-target scan loops.
  3. Drop SpellStatusV2 and Babble-Spell (O8, O9). Player cast events with spell IDs replace a library that hooks every spell you cast, and a 524 KB name table used for about 40 spells.
  4. AddOn Options pages built from the existing option tables (O15). Every plugin and boss setting appears in Game Menu › AddOn Options without editing 151 modules, and the FuBar menu goes.
  5. Exact-yard proximity and alerts that play with game sounds muted (O10, O11).

Gating

Decision needed first. Only your UHD client loads ClassicAPI.dll. The standard Turtle client’s dlls.txt doesn’t list it, and both clients share one Interface folder. After gating, the standard client would load only the stub and BigWigs would be off there. Either you play only the UHD client, or ClassicAPI is added to the standard client’s dlls.txt as well.

Backup

Before the first edit: C:\Gaming\World of Warcraft - Turtle\Interface\AddOns\BigWigs-2.0.6-pre-ClassicAPI.zip, with the BigWigs folder at its top level so extracting it restores the addon. The installed folder isn’t a git repo; your GitHub fork is. The recommended flow is to make each batch in a clone of the fork, install it, and commit only after you’ve tested it in game.

Things that must not change

  • Each module’s module.revision. Every sync name is built from it (for example "LucifronCurseRep"..module.revision). Changing it on a converted module would stop that module syncing with raid members on any other BigWigs build.
  • Sync names and the BigWigs X-Revision. They keep raid syncs and the version check working with other players.
  • SavedVariables. All saved data keeps its current tables and keys.

Bugs

Sure means traced through the code. Likely means the pattern is wrong but hasn’t been seen failing.

B1

CancelAuraId errors without SuperWoW

mediumsureCore.lua:1816
Scenario
Without GetPlayerBuffID, the function prints “Superwow required” and then calls it anyway, raising “attempt to call a nil value”. Echo of Medivh calls it (EchoOfMedivh.lua:228).
Fix
Find the buff with C_UnitAuras.GetUnitAuraBySpellID("player", id, "HELPFUL") and cancel it with CancelUnitBuff, with no SuperWoW dependency. Part of O6.
B2

Engage scan writes wipe mobs into the module’s enable list

lowsure, dormantCore.lua:898–913
Scenario
When enabletrigger is a table, IsBossInCombat inserts every wipe mob into that same table every 0.5 s while it waits for the pull. The table grows without limit, and the adds become enable triggers. No current module has both a table trigger and wipemobs, so it fires only for a future module.
Fix
Build a local list instead of writing into module.enabletrigger.
B3

Global variable leaks with generic names

lowsureluac SETGLOBAL
Scenario
About 30 accidental globals, including events (MageTools), b (FRBuffMacro), element (Ossirian.lua:263), debuffActive (Proximity.lua:606), _ (Bars, Messages, WarningSign), bwPlayerIsAttacking (shared by two modules), cocoonedPlayer, vanished, watchForSpawn and p2. Another addon using the same name can overwrite them, or be overwritten.
Fix
Make each one local, after checking it isn’t read from another file.
B4

Debuff checks miss Turtle’s overflow debuffs and need SuperWoW

mediumlikelyCore.lua:1996–2050
Scenario
BuffIsPresent and DebuffIsPresent read a spell ID from SuperWoW’s extra UnitBuff / UnitDebuff returns and only walk the 16 debuff slots. Turtle moves extra debuffs into buff slots once those are full, which is common on raid bosses. Ezzel’s cast-time scaling and Curse of Tongues check (Ezzel.lua:174–204) then give wrong timers.
Fix
Use C_UnitAuras.GetUnitAuraBySpellID(unit, id, "HARMFUL"), which sorts by real polarity. Part of O6.
B5

Two different SuperWoW checks

lowsureCore.lua:1064
Scenario
The core defines RegisterCastEventsForUnitName only when SUPERWOW_STRING or SetAutoloot is set. Nine modules (Ebonroc, Firemaw, Flamegor, Nefarian, ChessFight, Rupturan, Axelus and others) call it after testing SUPERWOW_VERSION or SetAutoloot. A SuperWoW build that defines one global and not the other would make those modules error at engage. Your SuperWoW sets both, so it works today.
Fix
Goes away with O4, which replaces the SuperWoW path. Otherwise, use one shared check.
B6

Class checks compare against English names

lowsure197 checks in 66 files
Scenario
UnitClass("player") == "Warrior" uses the localised first return, so on a non-English client every check is false: cooldown tracking in CommonAuras and class-specific alerts in the boss modules stay off. Jindo.lua:274–286 also has a duplicate Warrior branch that can never run. This doesn’t affect an English client.
Fix
Compare the second return, the English class token (select(2, UnitClass("player")) == "WARRIOR"). The change is mechanical.
B7

Anchors move when the UI scale changes during play

lowlikelyMessages, Bars, WarningSign, Proximity
Scenario
Positions are saved in screen units and restored once. If the UI scale or window size changes during the session, every anchor shifts until the next login. Your Messages fix (restore in OnEnable) covers only login.
Fix
O12: restore every anchor on UI_SCALE_CHANGED.
B8

Replaced Blizzard functions that other addons may also hook

lowlikelyRaidOfficer.lua:72–83 · ChessFight.lua:176–225
Scenario
RaidOfficer overwrites RaidGroupButton_OnDragStart / OnDragStop. Its guard checks for an addon named "unknownyet", which never exists. ChessFight replaces ChatFrame_OnEvent and later restores the copy it saved, which drops any hook another addon added in between.
Fix
RaidOfficer: drop the dead guard and keep the originals local. ChessFight: use the AceHook pattern BossBlock already uses, which unhooks cleanly.

O1

Combat-log dispatcher for boss modules

effort Lrisk Mreliability · language
Now
154 files register 1,025 CHAT_MSG_SPELL_* / CHAT_MSG_COMBAT_* events and match about 1,086 text patterns, for example trigger_curse = "afflicted by Lucifron's Curse." plus a separate resist pattern (Lucifron.lua:84–98).

Gain
Exact matches with no partial-text false positives, any client language, one event instead of about 11 per module, and resists or immunes detected without a second pattern.
Plan
Build the dispatcher, then convert three pilot modules: Lucifron (plain), Ragnaros (tank tracking) and Ebonroc (SuperWoW cast path). Further modules are converted on request, with each module’s syncs and revision unchanged. Turtle’s custom raids use custom spell IDs. Collect them from your own logs with ClassicAPI’s /replay (C_CombatLogReplay.GetEvents lists every spellID).
Risk
Events still arrive only for what the server sends nearby, as chat does. Spells hidden from the combat log fire nothing, so check each pilot module against a log.

O17

Wyrmguard vulnerabilities per unit, with that unit’s own raid mark

effort Mrisk MreliabilityWyrmguards.lua
Now
The module reads damage chat lines and calls a school the vulnerability when one hit passes a fixed number, for example 1,300 fire or 1,700 shadow (Wyrmguards.lua:117–259). Four things make it a guess:
  • Wrong mark: the mark comes from your current target (GetRaidTargetIndex("Target"), line 285), even when the hit was another player’s on a different Wyrmguard. That’s why bars often show the wrong icon or “No Icon”.
  • Units can’t be told apart: every Wyrmguard has the same name in chat.
  • Gear-dependent thresholds: a strong caster passes them on a non-vulnerable target, and a weak one misses them on the vulnerable one.
  • One bar per school per pull: two Wyrmguards with the same school show one bar. The flags are globals (B3), and nothing is shared with the raid.
Replace
Combat-log damage events through the O1 dispatcher. Each hit carries the destGUID of the exact Wyrmguard, its raid mark at that moment (destRaidFlags, bits COMBATLOG_OBJECT_RAIDTARGET1–8), spellId, the spell school, amount, resisted and critical.
  • Per-unit evidence: keep a record per GUID per school.
  • Relative test: compare non-crit hits of the same spell from the same caster across Wyrmguards. The vulnerable one stands out whatever the caster’s gear. Keep the fixed thresholds only as a fallback when there is nothing to compare.
  • Resists: a school that is fully or partly resisted rules itself out for that unit.
  • Raid sync: once a unit is decided, sync it to the raid as GUID, school and mark. Each player’s client then adds what it sees.
  • Display: one bar per Wyrmguard, for example “Skull · Fire Vulnerability”. The mark updates if the raid leader re-marks the unit, and the bar goes when that GUID dies (UNIT_DIED).
The aura
The database lists a “Double received damage” aura per school on Wyrmguards: Fire 33001, Nature 33002, Shadow 33003, Frost 33004, Arcane 33005. They have no icon. That only matters to the game’s buff display, so the open question is whether the server includes the aura in the unit’s aura list. The reference doesn’t say, so the first BWL run settles it.
Detection order
  1. Aura list: C_UnitAuras.GetUnitAuraBySpellID(unit, 33001…33005) on any Wyrmguard token. ClassicAPI’s mark1–mark8 tokens resolve to whichever unit wears each raid mark, so BigWigs can check every marked Wyrmguard directly ("mark8" is skull) and update when UNIT_AURA fires for a mark token. This is exact, needs no combat, and pairs each school with its mark by construction.
  2. Combat log: SPELL_AURA_APPLIED or SPELL_CAST_SUCCESS with those IDs, if the server logs the application while you are in range.
  3. Damage evidence: the relative-damage method above, as the fallback.
Whichever finds it first syncs GUID, school and mark to the raid.
Tests
Run in BWL before the Wyrmguard pulls.
  • With a Wyrmguard targeted: /script for i=33001,33005 do local a=C_UnitAuras.GetUnitAuraBySpellID("target",i) DEFAULT_CHAT_FRAME:AddMessage(i..": "..(a and a.name or "not found")) end
  • Once, to watch the combat log until the next reload: /script local f=CreateFrame("Frame")f:RegisterEvent("COMBAT_LOG_EVENT_UNFILTERED")f:SetScript("OnEvent",function()local _,e,_,_,_,_,_,_,_,_,_,i=CombatLogGetCurrentEventInfo()if i and i>33000 and i<33006 then ChatFrame1:AddMessage(e.." "..i)end end)
Gain
The right school on the right mark for each Wyrmguard, shared across the raid. It works whoever does the damage, and in any client language.
Keep
module.revision (20041) and the War Stomp sync name, so War Stomp bars still sync with raid members on other builds.

Each batch can be tested in game on its own. Items you skip are dropped from their batch.

Batch 1: gate and quick fixes

Test checklist

After batch 1

  • UHD client: BigWigs loads with the lilac “(Requires Classic API)” suffix and no login warning.
  • Standard client (no ClassicAPI): one chat line says BigWigs needs ClassicAPI, nothing errors, and logging in and out leaves your BigWigs settings intact for the UHD client.
  • Change the UI scale in Video Options, then open Edit Layout: all anchors stay where they were.
  • Set effects volume to 0 and run /bw test: the alert sounds still play.
  • A warning icon disappears after its duration.

After batch 2

  • Proximity window in a raid shows distances, nearest first, and sounds the alarm only inside the module’s range.
  • Echo of Medivh’s aura cancel works; Ezzel’s bars scale with Curse of Tongues even when the boss has 16+ debuffs.
  • Hovering over or nearing a boss nameplate enables its module without targeting it.

After batch 3

  • Shield Wall, Last Stand, Fear Ward and Challenging Shout bars appear for the raid, with the right target name.
  • A mage portal cast announces; a cancelled cast doesn’t.
  • Typing {skull} in raid chat still converts.
  • “Dazed” warnings appear in a boss fight.
  • Combat Announcement (if broadcasting is on) announces a Taunt or Kick with the target’s name and raid mark.
  • Spell Requests still finds your spells and its request and cooldown buttons work.
  • The C’Thun map tooltip shows raid marks.

After batch 4

  • Every page draws fully and scrolls; each control type changes the setting live and survives /reload.
  • The minimap button keeps its old position and icon, opens the options, drags, and hides from its checkbox.
  • Its right-click menu runs the local, sync and voice tests, and enables and disables BigWigs (the icon changes to match).
  • Version check and resist check windows list results.

After batch 5

  • Each pilot boss: engage, every timer, resist messages, boss-kill message and module disable match the old module.
  • A raid member on a different BigWigs build still receives your syncs.
  • Wyrmguards: each marked Wyrmguard gets its own bar with the correct mark and school, whoever lands the hits, and the bar goes when that Wyrmguard dies.

Out of scope / not recommended

  • Replacing Ace2’s core (events, saved data, modules, locales). It touches every file and every saved setting for little gain.
  • Rewriting CandyBar on statusBar:SetTimerDuration. One shared update loop already drives all bars, and the bars also draw text countdowns, pauses and emphasis moves that the timer doesn’t cover.
  • Converting all 151 boss modules at once. Pilot first; convert more on request.
  • Encounter start and end events. ClassicAPI writes ENCOUNTER_START and ENCOUNTER_END to the log file only; they aren’t Lua events.
  • Chat filters for BossBlock. ClassicAPI has no message-filter API, so the hooks stay.
  • MageTools event sources. Version 2 already uses nampower’s structured events, so the gain from moving it is small.
  • Range plugin. It only sets combat-log range CVars, and works as it is.
  • Ace3. None present.
